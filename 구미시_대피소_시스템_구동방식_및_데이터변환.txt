구미시 대피소 안내 시스템
구동 방식, 길찾기 알고리즘 및 데이터 변환 정리
작성 기준일: 2026-09-30

===============================================================================
1. 문서 목적
===============================================================================

이 문서는 구미시 대피소 안내 웹 프로젝트가 어떤 순서로 동작하는지,
차량/도보 길찾기와 침수 우회를 어떤 방식으로 계산하는지, 그리고 SHP 및
공공 API 데이터를 서버 판정용/지도 표시용 데이터로 어떻게 변환했는지를
설명한다.

중요한 전제는 다음과 같다.

- 이 프로젝트가 도로망의 Dijkstra 또는 A* 알고리즘을 직접 구현한 것은 아니다.
- 실제 도로망 경로 계산은 TMAP 차량/보행자 경로 API가 담당한다.
- Flask 서버는 TMAP 경로와 침수 폴리곤의 교차를 검사하고, 안전 경유점을
  생성하여 TMAP에 재요청하는 상위 우회 알고리즘을 담당한다.
- 임의의 직선이나 대각선을 최종 안내 경로로 사용하지 않고, TMAP이 반환한
  실제 도로/보행로 LineString만 화면에 표시한다.

3. 전체 구동 흐름
===============================================================================

1) 사용자가 웹 페이지를 연다.

2) 브라우저가 다음 데이터를 동시에 요청한다.
   - GET /api/config
     TMAP 키 설정 여부와 기본 지도 중심 좌표를 받는다.
   - GET /api/flood-zones
     지도 표시용 GeoJSON과 레이어 설명을 받는다.
   - GET /api/live-flood-zones
     관리자 승인 현재 침수구역을 받는다. 현재 침수 레이어는 항상 적용한다.

3) TMAP JavaScript SDK로 구미시 실제 지도를 생성한다.
   - 기본 중심: 위도 36.1195, 경도 128.3446
   - SDK 초기화에 실패하면 간이 대체 화면을 표시한다.

4) 사용자가 '현재 위치' 버튼을 누르면 브라우저 Geolocation API로 좌표를
   얻는다.
   - enableHighAccuracy: true
   - timeout: 8초
   - maximumAge: 60초

5) 현재 위치를 GET /api/shelters에 전달한다.
   서버는 각 대피소의 직선거리와 침수구역 교차 가능성을 계산하여 정렬한다.

6) 사용자가 대피소를 선택하거나 추천 대피소가 자동 선택되면 POST /api/route를
   호출한다.
   요청에는 다음 값이 포함된다.
   - 현재 위치 위도/경도
   - 대피소 ID
   - 이동 방식: pedestrian 또는 car
   - 침수 우회 사용 여부
   - 공식 실제 침수흔적 위험지역 포함 여부
   - 사용자 제공 SHP 기반 50년 빈도 레이어 포함 여부

7) Flask 서버가 TMAP 최초 경로를 요청하고 침수 교차 여부를 검사한다.

8) 침수구역과 교차하면 안전 경유점 후보를 생성하여 TMAP에 여러 번 재요청한다.

9) 후보 중 침수구역 내부 이동거리가 가장 짧은 실제 도로 경로를 선택한다.

10) 브라우저가 TMAP Polyline으로 최종 경로를 그리고 거리, 시간, 안내 문구,
    침수 우회 상태를 표시한다.

11) '현재 침수'는 ON/OFF 버튼 없이 항상 적용한다. GET /api/live-flood-zones로
    관리자 승인 구역을 받고 지도/목록/대피소 추천/경로 우회에 함께 사용하며,
    15초마다 승인 및 해제 상태를 확인한다.

12) 관리자는 /admin/reports에서 대기 중 신고를 승인하거나 현재 침수를 해제한다.
    승인된 좌표는 실제 거리 기준 반경 40m 원형 폴리곤으로 변환된다.

13) 해제된 신고도 SQLite에서 삭제하지 않고 신고/승인/해제 일시와 좌표를
    이력으로 보존한다. 관리자는 상태별로 조회하거나 Excel 파일로 내보낼 수 있다.

14) 데모가 필요하면 실제 침수흔적 history.wkb 내부에서 추출한 고정 좌표 15개를
    source="demo"로 저장한다. 사용자 신고와 달리 지도에서 주황색으로 표시하며,
    sample_key를 사용하여 시드 스크립트 재실행 시 중복 삽입을 막는다.

4. 대피소 추천 방식
===============================================================================

대피소 목록의 1차 추천은 실제 TMAP 경로를 모두 호출하지 않고 빠르게 계산하기
위한 사전 점수 방식이다.

1) Haversine 공식으로 현재 위치와 대피소 사이의 지표면 직선거리를 계산한다.

   a = sin²(위도차/2)
       + cos(출발위도) * cos(도착위도) * sin²(경도차/2)

   거리 = 지구 반지름 * 2 * atan2(sqrt(a), sqrt(1-a))

2) 현재 위치-대피소 직선이 침수 폴리곤과 교차하는지 검사한다.

3) 아래 점수를 계산한다.

   추천 점수 = 직선거리(m) + 1,200 * 교차 침수구역 수

4) 추천 점수가 낮은 순서로 정렬한다.

주의:
이 점수는 목록을 빠르게 정렬하기 위한 1차 추천값이다. 최종 안내에서는 반드시
TMAP이 계산한 실제 도로 경로를 다시 검사한다.


===============================================================================
5. TMAP 차량/도보 경로 요청
===============================================================================

[차량]
- API: https://apis.openapi.sk.com/tmap/routes
- searchOption: 0
- carType: 0

[도보]
- API: https://apis.openapi.sk.com/tmap/routes/pedestrian
- searchOption: 30
- speed: 4

[공통]
- 요청 좌표계: WGS84GEO
- 응답 좌표계: WGS84GEO
- 경유점은 passList에 "경도,위도_경도,위도" 형식으로 전달한다.
- 경유점은 최대 5개만 전달한다.

TMAP 응답에는 Point와 LineString Feature가 함께 들어온다.

- Point Feature: 회전, 횡단보도, 이동 설명 등 안내 단계에 사용
- LineString Feature: 실제 지도 경로선에 사용

경유점을 사용한 TMAP 응답에는 실제 도로선이 아닌 보조 연결선이 포함될 수 있다.
따라서 app.py의 _extract_tmap_route()는 properties.index가 있는 LineString을
우선 사용하고, index가 없는 보조 연결선은 제외한다. 이 처리를 통해 지도에
길이 없는 곳을 가로지르는 대각선이 표시되는 문제를 방지했다.

각 LineString은 index 순으로 정렬한다. 이전 선분의 마지막 점과 다음 선분의
양 끝점 거리를 비교하여 방향이 반대이면 좌표 배열을 뒤집는다. 최종 응답에는
다음 두 형태를 함께 저장한다.

- path: 전체 경로 좌표를 순서대로 연결한 배열
- pathSegments: TMAP이 제공한 실제 도로 선분 단위 배열

지도에는 pathSegments를 각각 그리므로 떨어진 선분 사이를 임의 직선으로
연결하지 않는다.

6. 침수 교차 판정 방식
===============================================================================

서버 시작 후 FloodRepository가 WKB 파일을 읽는다.

[기본 사용 데이터]
- history.wkb: 실제 침수흔적

[50년 예상 옵션 사용 시 추가]
- river.wkb: 50년 빈도 지방하천 하천범람 예상
- urban.wkb: 50년 빈도 도시침수 예상

각 결합 도형을 개별 Polygon/MultiPolygon 조각으로 분리한 뒤 STRtree 공간
인덱스를 생성한다. 실제 경로를 LineString 또는 MultiLineString으로 변환하고
다음과 같이 검사한다.

1) STRtree에서 경로의 영역과 겹칠 가능성이 있는 도형만 빠르게 검색한다.
2) predicate="intersects"로 실제 교차하는 폴리곤만 선택한다.
3) 교차 폴리곤의 ID, 데이터 종류, 이름, 경계, 원본 도형을 반환한다.

모든 폴리곤을 매번 순회하지 않고 공간 인덱스를 사용하므로 데이터가 많아도
교차 판정 범위를 줄일 수 있다.


===============================================================================
7. 침수 우회 경로 알고리즘
===============================================================================

이 프로젝트의 우회 알고리즘은 "TMAP 실제 도로망 + 침수 폴리곤 기반 경유점
재탐색" 방식이다.

7.1 최초 경로 계산
------------------

1) 경유점 없이 TMAP에 출발지-대피소 경로를 요청한다.
2) TMAP이 반환한 실제 차량/보행 경로와 침수 폴리곤의 교차를 검사한다.
3) 교차가 없으면 최초 경로를 그대로 사용한다.
4) 교차가 있으면 해당 침수 폴리곤을 기준으로 우회 후보를 생성한다.


7.2 우회 후보 A: 침수구역 외곽 경유점
------------------------------------

교차한 침수구역의 bounds를 이용하여 남쪽, 북쪽, 서쪽, 동쪽 외곽 경유점을
만든다. 각 방향은 모서리-중앙-모서리의 3개 점으로 구성된다.

[도보 여유 간격]
- 데이터 종류별 기본 detour_margin_deg 사용

[차량 여유 간격]
- max(기본 간격 * 1.5, 0.006도)
- max(기본 간격 * 2.0, 0.008도)

차량은 도보보다 도로망 제약과 회차 거리가 크므로 더 넓은 간격을 사용한다.


7.3 우회 후보 B: 원래 경로와 평행한 좌우 경유점
--------------------------------------------------

출발지-목적지 벡터를 미터 좌표로 근사하고 수직 단위벡터를 구한다. 원래 이동
방향의 5%, 35%, 50%, 65%, 95% 위치를 좌우로 이동시켜 평행 우회 후보를 만든다.

[도보 좌우 이동거리]
- 최소 약 90m
- 최소 약 140m
- 침수구역 기본 여유 간격이 크면 그 값을 우선 적용

[차량 좌우 이동거리]
- 최소 약 450m
- 최소 약 700m
- 침수구역 기본 여유 간격의 1.5배/2배가 더 크면 그 값을 적용

외곽 후보는 큰 폴리곤을 돌아가는 데 유리하고, 평행 후보는 가까운 옆 도로로
빠지는 데 유리하다. 어느 한 종류만 상위 후보를 모두 차지하지 않도록 두 후보군을
교대로 섞는다.

이 방식은 다음 실제 테스트 문제를 해결하기 위해 적용했다.

- 좌표 36.11856, 128.36556에서 도량동 대피소까지 차량 경로
- 기존 실제 침수이력 교차거리: 약 98m
- 수정 후 실제 침수이력 교차거리: 0m
- 수정 후 TMAP 차량 경로거리: 약 7.0km


7.4 후보 정리
-------------

- 경유점이 침수 폴리곤 내부에 있으면 해당 후보는 제외한다.
- 같은 좌표 조합은 중복 제거한다.
- 경유점은 출발지-목적지 진행 방향 투영값으로 정렬한다.
- 여러 침수구역이 있더라도 TMAP passList 제한에 맞게 최대 5개로 축약한다.
- 도보는 최대 6개 후보, 차량은 최대 8개 후보를 실제 TMAP에 재요청한다.
- 침수구역 외곽 후보와 평행 후보를 번갈아 평가하여 후보 다양성을 유지한다.


7.5 최종 경로 평가식
-------------------

각 TMAP 후보 경로를 다시 침수 도형과 교차 검사한 후 다음 튜플을 비교한다.

   (침수구역 내부 이동거리, 남은 위험구역 수, 전체 경로거리)

앞의 값이 가장 작은 후보를 우선한다.

1순위: 침수구역 안에서 이동하는 총 예상거리
2순위: 완전히 피하지 못한 위험구역 수
3순위: TMAP 전체 경로거리

따라서 폴리곤 ID 한 곳을 길게 통과하는 경로보다 여러 작은 폴리곤을 짧게
스치는 경로가 더 안전하면 후자를 선택할 수 있다. 완전 우회 경로의 침수 내부
이동거리는 0m이므로 항상 위험 경로보다 우선한다.


7.6 침수구역 내부 이동거리 계산
--------------------------------

1) TMAP pathSegments 각각을 Shapely LineString으로 만든다.
2) STRtree로 선분과 교차하는 침수 폴리곤을 조회한다.
3) line.intersection(flood_polygon)으로 침수구역 안쪽 선분만 잘라낸다.
4) 한 선분에서 여러 침수 폴리곤이 겹치면 union_all로 중복 길이를 제거한다.
5) WGS84 각도 좌표를 아래 비율로 미터에 근사한다.

   경도 1도 = 111,320 * cos(중심 위도) m
   위도 1도 = 110,574 m

6) 각 선분의 침수 내부 길이를 합산한다.

선분별로 계산하므로 같은 위험도로를 실제 경로가 왕복하면 왕복한 거리만큼
노출거리도 다시 합산된다.


7.7 우회 결과 상태
------------------

- clear
  최종 경로가 침수구역과 교차하지 않음

- partial
  재탐색 후에도 일부 침수구역이 남음. 최초 대비 노출거리가 줄었다면 감소율과
  최초/최종 거리를 표시함

- unavoidable
  출발지, 대피소 또는 대피소 인근 차량 진입도로가 침수구역에 포함됨

- disabled
  사용자가 침수 우회 옵션을 끔

차량은 대피소에서 약 150m 이내의 침수 폴리곤도 별도로 검사한다. 대피소 좌표
자체가 폴리곤 밖이더라도 실제 진입도로가 현재 또는 실제 이력 침수구역 안에 있으면
"대피소 인근 진입도로 우회 불가" 경고를 표시한다.

50년 빈도 버튼을 켜면 사용자 제공 하천범람·도시침수 SHP 변환자료도 이 검사에
포함한다. 선택된 침수구역을 완전히 피할 수 없을 때는 존재하지 않는 안전
경로를 임의로 그리지 않고, 가장 노출이 짧은 실제 TMAP 경로와 우회 불가
경고를 함께 제공한다.

8. SHP 파일 변환 방식
===============================================================================

대상 파일:
- 구미시 50년 빈도 지방하천 하천범람지도 SHP
- 구미시 50년 빈도 도시침수지도 SHP

실행 파일:
- scripts/process_flood_shapefiles.py

처리 순서:

1) pyogrio.raw.read()로 SHP의 메타데이터, 필드, Geometry WKB를 읽는다.

2) shapely.from_wkb(..., on_invalid="fix")로 Geometry를 생성한다.
   가능한 경우 잘못된 도형을 읽는 과정에서 복구한다.

3) SHP 메타데이터의 원본 CRS에서 EPSG:4326으로 변환한다.

   Transformer.from_crs(
       원본 CRS,
       "EPSG:4326",
       always_xy=True
   )

   always_xy=True를 사용하여 입력 순서를 경도(X), 위도(Y)로 고정한다.

4) shapely.union_all()로 같은 데이터셋의 모든 도형을 하나의 결합 도형으로
   만든다.

5) 결합 결과가 유효하지 않으면 shapely.make_valid()로 복구한다.

6) 정밀 판정용 WKB를 저장한다.
   - river.wkb
   - urban.wkb
   - 2차원 좌표로 저장
   - 단순화하지 않은 정밀 도형 사용

7) 지도 표시 성능을 위해 별도의 단순화 도형을 만든다.
   - river: simplify 0.0003도
   - urban: simplify 0.00015도
   - preserve_topology=False

8) 단순화 도형과 이름, 색상, 위험도, 원본 Feature 수 등의 속성을 GeoJSON으로
   만든다.

9. 실제 침수흔적 API 데이터 변환
===============================================================================

실행 파일:
- scripts/fetch_recent_flood_traces.py

사용 API:
- 행정안전부 재난안전데이터 공유 플랫폼 DSSP-IF-00117

처리 순서:

1) 첫 페이지를 호출하여 totalCount를 확인한다.

2) 페이지당 1,000건씩 전체 페이지를 조회한다.
   - 기본 병렬 작업 수: 4
   - 페이지 호출 실패 시 최대 3회 재시도
   - 재시도 사이에 1.5초, 3초 대기

3) 구미시 시군구 코드 47190만 선택한다.

4) 요청한 연도 범위만 선택하고 GEOM이 없는 행을 제외한다.

5) GEOM WKT 문자열을 shapely.from_wkt(..., on_invalid="fix")로 변환한다.

6) API Geometry의 원본 좌표계 EPSG:3857을 지도/경로 좌표계 EPSG:4326으로
   변환한다.

7) 모든 실제 침수이력 도형을 union_all()로 결합하고 필요하면 make_valid()로
   복구한다.

8) 정밀 판정용 history.wkb를 저장한다.

9) 지도 표시용 도형은 0.00004도로 단순화한다.
   실제 이력은 작은 흔적을 보존하기 위해 예상지도보다 낮은 단순화 값을 쓰며,
   preserve_topology=True를 적용한다.

10) history, river, urban 레이어를 하나의
    flood_zones.gumi.web.geojson FeatureCollection으로 만든다.

현재 생성 데이터:
- 실제 침수흔적 기본 레이어: 2012년 22건 + 2018년 2건 = 총 24건
- 2021~2025년 구미시 공식 등록 결과: 0건
- 실제 이력은 기본 활성화
- 50년 빈도 예상지도는 사용자가 체크할 때만 활성화

따라서 50년 예상지도는 최근 5년 실제 발생 데이터가 아니라 시뮬레이션
시나리오이며, 실제 침수흔적 레이어와 의미가 다르다.

10. 정밀 판정용 WKB와 표시용 GeoJSON을 분리한 이유
===============================================================================

[WKB]
- 서버 전용
- 원본에 가까운 정밀 Geometry
- Shapely가 빠르게 읽을 수 있는 바이너리 형식
- 침수 교차 여부와 노출거리 계산에 사용

[GeoJSON]
- 브라우저 지도 표시 전용
- 좌표 수를 줄인 단순화 Geometry
- JavaScript와 TMAP Polygon이 직접 사용하기 쉬움
- 네트워크 전송량과 브라우저 렌더링 부하 감소

지도에서 보이는 단순화 도형으로 안전 판정을 하지 않고, 서버의 정밀 WKB로
판정한다. 따라서 표시 성능을 줄이면서도 판정 정확도는 가능한 한 유지한다.

11. 공식 이재민 임시주거시설 데이터 변환
===============================================================================

scripts/fetch_gumi_shelters.py는 재난안전데이터 공유 플랫폼의
행정안전부_이재민 임시주거시설 전용 API(DSSP-IF-10945)를 페이지 단위로
조회한 뒤 다음 조건을 모두 만족하는 레코드만 선택한다.

- ARCD 또는 BDONG_CD가 구미시 코드 47190으로 시작
- LA/LO가 유효한 구미시 인근 좌표

이 데이터셋 자체가 이재민 임시주거시설 전용이므로, 범용 수용시설공간 API의
수용구분코드를 임시주거시설 분류값으로 해석하지 않는다.

선택된 원본 필드는 다음과 같이 앱 필드로 변환한다.

- ACMDFCLTY_SN -> id, facilitySerial
- VT_ACMDFCLTY_NM -> name
- VT_ACMD_PSBL_NMPR -> capacity
- LA -> lat
- LO -> lng
- FCLTY_AR -> areaM2
- ACMDFCLTY_SE_CD -> facilityCategoryCode
- BDONG_CD -> legalDongCode

원본 RN_DTL_ADRES 또는 DTL_ADRES를 주소로 사용한다. 두 주소가 모두 비어 있는
시설만 LA/LO 좌표를 TMAP reversegeocoding API에 전달하여 보완한다. 호출 제한을
피하기 위해 주소 변환은 기본 1개 작업자로 순차 처리한다.

변환 결과는 다음 형태의 JSON 배열이다.

  "name": "시설명",
  "type": "이재민 임시주거시설",
  "address": "경상북도 구미시 ...",
  "lat": 36.12,
  "lng": 128.34,
  "capacity": 100,
  "verified": true,
  "source": "safetydata_DSSP-IF-10945",
  "facilitySerial": "시설일련번호",
  "facilityCategoryCode": "시설구분코드",
  "legalDongCode": "47190...",
  "areaM2": 500
}

기존 scripts/import_shelters_csv.py는 별도로 받은 CSV를 수동 변환해야 할 때 쓸
수 있다. 여러 공공데이터 CSV 헤더 이름을 다음 내부 필드로 통합한다.

- name: name, 시설명, 대피소명, FCLT_NM
- address: address, 주소, 도로명주소, RONA_DADDR, LOTNO_DADDR

  "lat": 36.12345,
  "lng": 128.12345,
  "capacity": 500,
  "verified": true,
  "source": "imported_csv"

12. 프런트엔드 지도 표시 방식
===============================================================================

1) 침수 GeoJSON의 Polygon/MultiPolygon 외곽 좌표를 Tmapv2.Polygon으로 그린다.

2) datasetType="live"인 관리자 승인 신고를 '현재 침수'로 기본 표시한다.
   - 신고 위도에서 경도 1도의 실제 길이를 보정하여 반경 40m 원을 만든다.
   - 표시 목록과 차량/도보 우회 판정에도 같은 폴리곤을 사용한다.
   - 관리자가 침수 해제하면 다음 15초 주기 조회에서 지도와 목록에서 제거된다.

3) history 실제 침수흔적은 '침수 위험지역' 체크 시에만 표시하고 우회 판정에
   포함한다.

4) datasetType="scenario"인 river/urban은 별도 '50년 빈도' 체크 시에만 표시하고
   우회 판정에 포함한다. 두 자료는 사용자 제공 SHP의 변환 결과만 사용한다.

5) 현재 위치와 대피소는 Tmapv2.Marker로 표시한다.

6) 최종 경로의 pathSegments 각각을 Tmapv2.Polyline으로 그린다.
   - 안전 경로: 청록색
   - 위험구역이 남은 경로: 주황색

7) 경로 전체 좌표로 지도 bounds를 맞춘다.

8) 서버가 반환한 다음 값을 이용해 상태 메시지를 표시한다.
   - detectedRiskZones
   - riskZones
   - avoidedRiskZones
   - accessLimitedRiskZones
   - avoidanceStatus
   - initialRiskDistanceM
   - riskDistanceM
   - riskReductionPercent
   - warning

9) 지도 하단 경로 상태는 침수 판정 결과에 따라 색상을 구분한다.
   - 초록색: 실제 경로에 침수 위험지역 교차 없음
   - 파란색: 경유점 재탐색으로 침수구역 우회 완료
   - 주황색: 완전 우회 불가, 위험 노출거리 감소 또는 경고 있음
   - 빨간색: 침수 위험지역 통과, 우회 불가 또는 경로 계산 오류

14. 캐시와 성능 처리
===============================================================================

- 대피소 JSON은 lru_cache(maxsize=1)로 한 번만 읽는다.
- 사용자 API가 사용하는 실제 이력 저장소는 lru_cache로 재사용한다.
- 변환된 예상지도 파일은 보관하지만 사용자 API의 저장소에는 추가하지 않는다.
- 표시용 GeoJSON도 lru_cache(maxsize=1)로 캐시한다.
- STRtree를 사용하여 경로 주변 후보 폴리곤만 검사한다.
- 서버 판정에는 정밀 WKB를 사용하고 브라우저에는 단순화 GeoJSON을 보낸다.
- TMAP 재요청 수를 제한하여 무한 탐색을 방지한다.
- 위치 신고는 SQLite에 저장하고 관리자 조회는 최신 500건으로 제한한다.
- 기본 요청은 승인된 현재 침수 폴리곤으로 STRtree를 구성한다.
- 침수 위험지역이 켜지면 실제 이력 WKB만 같은 STRtree에 추가한다.
- 50년 빈도가 켜지면 사용자 제공 SHP에서 변환한 river/urban WKB를 추가한다.
- 정적 위험자료만 사용하는 기존 API 요청은 캐시된 정적 저장소를 재사용한다.


===============================================================================
15. 오류 및 대체 처리
===============================================================================

TMAP 키가 없거나 TMAP 경로 API 호출에 실패하면 서버는 로컬 대체 경로를
반환할 수 있다. 이 경로는 출발지, 경유점, 목적지를 직선으로 연결한 것으로
실제 도로망 경로가 아니다. 응답 source는 local-fallback이며 경고 문구를 함께
제공한다.

따라서 운영 환경의 실제 대피 안내에서는 TMAP 연결 실패 시 로컬 직선 경로를
안전한 도로 안내로 취급하면 안 된다. 화면에 서비스 장애를 명확히 알리거나
경로 안내를 중단하는 정책을 추가하는 것이 바람직하다.

17. 현재 한계와 운영 전 보완사항
===============================================================================

1) 대피소 데이터는 공식 API를 실행한 시점의 정적 스냅샷이다.
   운영 환경에서는 scripts/fetch_gumi_shelters.py를 주기적으로 실행하여 시설의
   사용 여부, 좌표, 수용인원 변경을 반영해야 한다.

2) TMAP은 사용자 정의 침수 Polygon을 직접 회피하는 옵션을 제공하는 것이
   아니라 경유점을 통해 우회시키는 구조이다. 따라서 도로망 구조에 따라 완전
   우회가 존재하지 않거나 후보 탐색 범위 밖에 있을 수 있다.

3) 50년 빈도 자료는 실제 최근 침수기록이 아니라 넓은 범위를 가정한 자료이다.
   기본값은 OFF이며, 사용자가 별도 버튼으로 켰을 때만 화면, 대피소 추천,
   차량/도보 우회 판정에 포함한다.

4) 실제 재난 시에는 도로 통제, 실시간 강우, 수위, 교량 통제, 공사 구간 등의
   정보가 추가로 필요하다. 현재 시스템은 정적 침수 도형과 TMAP 경로를
   결합한 프로토타입이다.

5) 대피소 추천 1차 점수는 직선거리 기반이다. 모든 대피소에 대해 실제 TMAP
   안전 경로를 미리 계산하는 방식으로 확장하면 추천 정확도를 높일 수 있지만,
   API 호출량과 응답시간이 증가한다.

6) 브라우저 위치정보는 사용자 권한이 필요하다. 운영 배포에서는 HTTPS를
   사용해야 안정적으로 Geolocation API를 사용할 수 있다.

7) TMAP JavaScript SDK 키는 브라우저에서 사용되므로 SK open API 콘솔에서
   허용 도메인을 운영 도메인으로 제한해야 한다.

8) 관리자 신고 페이지에는 아직 로그인 기능이 없다. 운영 환경에서는 승인/해제
   API와 관리자 화면에 인증 및 권한 검사를 반드시 추가해야 한다.


===============================================================================
18. 핵심 요약
===============================================================================

- 실제 길찾기: TMAP 차량/보행자 도로망 API
- 대피소: 공식 이재민 임시주거시설 전용 API DSSP-IF-10945
- 대피소 필터: ARCD 또는 BDONG_CD가 구미시 코드 47190으로 시작
- 대피소 주소: 공식 주소 우선, 누락된 경우에만 TMAP 역지오코딩으로 보완
- 침수 판정: Shapely + 정밀 WKB + STRtree
- 우회 방식: 침수구역 외곽/평행 경유점 생성 후 TMAP 반복 요청
- 최종 선택: 침수 내부 이동거리 -> 남은 위험구역 수 -> 전체 거리 순
- 좌표계 통일: SHP 원본 CRS 또는 EPSG:3857 -> EPSG:4326
- 서버 판정 데이터: 단순화하지 않은 WKB
- 지도 표시 데이터: 단순화한 GeoJSON
- 실제 이력: 2012년/2018년 공식 침수흔적 24건
- 선택 위험지역: 공식 실제 침수흔적만 표시 및 우회 판정에 포함
- 50년 빈도: 사용자 제공 river/urban SHP 변환자료만 별도 선택
- 현재 침수: 관리자 승인 신고 좌표 중심 반경 40m, 버튼 없이 항상 표시/우회 포함
- 실시간 상태: pending(대기) -> active(현재 침수) -> resolved(해제)
- 침수 이력: 신고/승인/해제 시각과 좌표 보존, 관리자 조회 및 Excel 내보내기
- 관리자 직접 등록: 지도 클릭 좌표를 즉시 active 반경 40m 구역으로 추가
- 데모 침수: 실제 침수흔적 내부 15개 고정 좌표, 주황색 표시, 중복 시드 방지
- 경로 표시: TMAP이 반환한 index 기반 실제 LineString만 사용
- 완전 우회 불가 시: 위험구간 감소율 또는 대피소 진입도로 경고 표시
